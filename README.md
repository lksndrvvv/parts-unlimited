# parts-unlimited
Практическая 3 — Программная инженерия. 
Управление календарем и графиками поставок решений.

## Цель работы

Научиться планировать задачи программного проекта, распределять их между командами, управлять сроками выполнения и составлять общий календарный план поставки продукта.

В лабораторной работе вместо Azure DevOps используется бесплатная платформа GitHub.

## Используемые инструменты

- GitHub Repository — хранение проекта.
- GitHub Issues — создание и управление задачами.
- GitHub Projects — планирование и отслеживание работ.
- GitHub Roadmap — календарный план проекта.
- GitHub Milestones — контрольные даты проекта.

## Ход работы

### 1. Создание проекта

Был создан репозиторий `parts-unlimited` для учебного проекта Parts Unlimited.

Также был создан GitHub Project для управления задачами и сроками разработки веб-приложения.

### 2. Создание плана поставки

В GitHub Projects создан календарный план «Поставка Веб-приложения» с использованием представления Roadmap.

Для задач настроены статусы, даты начала и окончания, спринты и принадлежность к командам.

Добавлена фильтрация завершённых задач по условию `-status:Done`.

### 3. Настройка календаря

Создана контрольная дата «Команда в отпуске» — 30 октября 2026 года.

Рассмотрены разные масштабы календаря для отображения краткосрочных и долгосрочных работ.

### 4. Создание рабочих команд

В проекте выделены две команды:

**Parts Unlimited Team** — основная команда разработки веб-приложения.

**External integrations** — команда для интеграции с внешними сервисами.

Для основной команды предусмотрены четыре спринта.

Для команды External integrations настроены две итерации:

- Итерация 50: 13.10.2026–30.10.2026.
- Итерация 51: 02.11.2026–20.11.2026.

### 5. Создание задач

В GitHub Issues созданы задачи разработки веб-приложения:

- Разработка каталога автозапчастей.
- Реализация поиска по каталогу.
- Реализация корзины заказов.
- Разработка пользовательского интерфейса.
- Предоставить пользователям возможность отслеживания посылок.
- Реализация работы с данными по доставкам.
- Тестирование веб-приложения.

Для команды External integrations добавлены задачи:

- Интеграция с метеорологической службой.
- Интеграция с корпоративными данными доставок.

Задачи распределены между командами и итерациями.

### 6. Анализ графика поставок

При анализе календарного плана была обнаружена зависимость между задачами двух команд.

Основная команда планировала реализовать отслеживание посылок раньше, чем команда External integrations могла предоставить необходимые данные о доставках.

Для решения проблемы были изменены сроки выполнения задач:

- Интеграция с корпоративными данными доставок перенесена в Итерацию 50.
- Интеграция с метеорологической службой перенесена в Итерацию 51.
- Работа с данными доставок перенесена в Sprint 4.
- Срок реализации отслеживания посылок согласован со сроком интеграции.

После изменений график поставок стал более согласованным.

## Результат работы

В результате лабораторной работы был создан учебный проект Parts Unlimited на платформе GitHub.

Были настроены задачи, рабочие команды, спринты, итерации и календарный план поставки веб-приложения.

Проведён анализ зависимости между задачами и выполнено перераспределение работ для согласования сроков.

## Вывод

В ходе лабораторной работы были изучены возможности управления календарём и графиками поставок программных решений.

Было показано, что основные задачи планирования, распределения работ между командами и контроля сроков можно выполнить средствами бесплатной платформы GitHub без использования Microsoft Azure DevOps.
